05 / 萃取

每次先問：要搬多少

來源很雜：資料庫、Excel／CSV、API、Log、感測、Google 表、電商 SaaS。

全量
小資料或第一次

整包搬走，適合建置，不適合天天跑。

增量
正式營運的預設

只抓新增與異動。updated_at > 上次執行

CDC
追變更本身

異動很勤的表，跟著變更走。

記得分頁、限流、失敗重試，而且每次都寫 log。

07 / 成敗在這裡

轉換才是成敗

搬得動不算完成。清得乾淨、對得上、算得出來，才算。

八個動作
洗到可以拿來算
  • 空值、重複先清掉
  • 日期、幣別講同一種話
  • 代碼要對上名稱
  • 多張表 JOIN 得起來
  • 做成日、月彙總
  • 算出毛利率、成長率
  • 金額不能是負的
  • 最後再去重一次
六問
資料品質過不過
  • 完整：該有的有沒有
  • 正確：數字真不真
  • 一致：同一件事同一種寫法
  • 唯一：同一筆不要出現兩次
  • 及時：現在看還算新鮮
  • 合法：能不能這樣用
這關沒過，後面的模型只是算得很認真的錯。

08 / 載入

放錯地方，重跑就變兩筆

倉儲給管理報表，資料超市給部門，資料湖留原始，向量庫給 RAG。

Append
只往後加

流水、log。舊的不要改。

Upsert
有就更新

訂單、會員、商品。同一筆還是同一筆。

Overwrite
整表覆蓋

小主檔、每日快照。表不大才這樣做。

慢變
歷史要留著

價格、等級不能直接蓋掉。

同一筆訂單，不能因為重跑就變成兩筆。

09 / 主管也聽得懂

中間是事實，周圍是切法

先畫一顆星。先不要展開全部欄位。

事實
發生了什麼

賣了多少、多少錢。這張表記事件。

維度
從哪個角度切

門市、商品、日期。拿來切片。

例子
fact_sales

掛上 store、product、date。一顆星就夠。

主管要聽的是：賣了什麼、在哪裡、哪一天。不是欄位清單。

10 / 先洗還是先倒

先洗再入，還是先倒再洗

實務多半混著做：Raw → Staging → Transform → 整理好的表 → 分析。

ETL
先洗再入倉

傳統倉儲。品質要先過關，才進得去。

ELT
先倒進去再洗

雲端倉儲、dbt 這條路。彈性大，治理不能省。

ELT 很彈性；治理不夠，資料湖會變成資料沼澤。

11 / 走完一輪

用門市銷售把同一條線走完

來源：POS、商品主檔、門市主檔、天氣、促銷。還是來源 → 萃取 → 暫存 → 轉換 → 倉儲 → 報表。

營收
賣了多少錢

這段期間、這家門市的金額。

來客數
TC，來了多少人

人來了沒有，先跟金額分開看。

客單價
每人平均花多少

營收除以來客數。口徑要全公司一樣。

成長率
跟上一期比

長還是縮。比的期間要先講清楚。

MAPE 用一句話：預測跟實際差多少百分比。
