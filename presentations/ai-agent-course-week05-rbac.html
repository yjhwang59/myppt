角色 / 先對詞 · 對齊第 1 週

CRUD、API、RBAC 各用一句話

CRUD
資料會怎麼變

新增、讀取、更新、刪除。上週的使用者管理就是這四個。

API
兩邊說好的入口

前端請後端做事的門口。例如送出詢問是一個，查詢問清單是另一個。

RBAC
依角色，不依人

角色權限控管。先定角色能做什麼，再把人放進角色。

這三句對齊第 1 週投影片，也對齊公開詞彙表：RBAC 是依使用者角色決定可查看或操作哪些功能。

角色 / 18:48–19:10

人會換，角色比較穩

依人
每一個人各寫一條
  • 小王可以刪、小陳不行
  • 人一離職就要改程式
  • 很容易漏
依角色
先寫角色，再派人
  • 客服都不能刪
  • 新人只要指定成客服
  • 規則只維持三份
Northgo 詢問處理用三個角色：管理員、業務、客服。英文對照是 admin、editor、viewer 的想法，但課堂用中文角色名。

把關 / 畫面和伺服器

藏起來給人看，403 才是把關

畫面
依角色少放按鈕
  • 客服看不到刪除
  • 客服看不到帳號管理
  • 業務看得到詢問，看不到帳號
伺服器
每條 /api/admin 都查
  • 不允許就回 403
  • 正文寫「你沒有這個權限」
  • 不要順便改到資料
名詞｜403：伺服器拒絕這次請求。人還是登入了，只是這個動作不準做。跟「沒登入」不是同一件事。
