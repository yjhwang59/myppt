02 / 為什麼重要

Agent 幫你選服務、動手裝——你信得過嗎？

你隨口說「找個資料庫」，過幾分鐘它就選好廠商、寫好設定。心裡那個問題很實際：它為什麼選這家？

01
畫面很熟

打開 Cursor 或 Claude Code，它選好、排好下一步，你點頭它就裝。事情好像結束了。

02
重點不是誰最紅

Armature 想搞清楚的是：Agent 怎麼發現工具、怎麼挑，最後又是誰勝出。

03
別只看推薦清單

對教 Agent、自己專案也天天用的人來說：先搞懂判斷從哪來，再決定要不要信。

白話結論：重要決定還是自己看一眼理由和限制條件，比較安心。

04 / 觀察 1

三個 Agent 找資料習慣差很大

碰到同一題、選到同一工具的比例，大概只有 42%。換一個 Agent，答案可能整組換掉。

~2/3
Cursor 會上網查

大概三分之二的會話會上網。語音那類它常走出自己的路，例如選 Vapi。

~94%
Codex 幾乎必搜

十次有九次還會用 site: 這類語法，把搜尋鎖在比較可信的站或特定產品官網。

~30%
Claude Code 較少上網

但一旦查，瀏覽頁數大約是 Codex 的三倍。比較愛自己從頭做：約 19%，差不多是另外兩個的兩倍（約 10%）。

語音相關甚至各走各的：Claude Code 選 Twilio、Codex 選 OpenAI Realtime API、Cursor 選 Vapi。

07 / 觀察 4

官網一句話，就能翻盤

很多時候是怎麼寫、怎麼呈現觸發了顧慮，不一定真的硬失格。

定價
Mailgun 常輸 Postmark

Agent 讀到免費方案「郵件只留一天」，這一句就夠讓它改選。

包裝
Supabase 整包綁太滿

Auth、Storage、Realtime 綁成一套，但 Agent 當下其實只要「純資料庫」。

觀感
煩跟貴都會被寫進理由

約 388 場提到「平台管理很煩」、195 場提到成本——常常是呈現方式觸發的。

08 / 觀察 5

有的賽道一面倒，有的咬得很緊

不是每個類別都有「默認贏家」。有些幾乎鎖定，有些兩家一直拉鋸。

支付
Stripe 十場贏九場

多半只有特定歐盟監管情境，才會讓給更專精的玩家，例如 Paddle、Mollie。

資料庫
Neon 大約拿下 66%

其餘多半是雲平台原生方案。Supabase 常被提到，但仍常輸給它。

檔案
S3 約 45%，沒有碾壓

Amazon S3 領先，Azure、GCP 各約 20%，這條賽道沒那麼一面倒。

Email
Resend 與 Postmark 膠著

Resend 約 35.6%、Postmark 約 27.4%，兩家咬得很緊。

09 / AIDC 實務

依任務裝工具 → 改碼 → 開 PR

在 myppt、fyhGoogle、aidc-work，我們多半先開 Cursor 雲端代理，對準目標 repo。這條路跟 Armature 看到的模式很像，差別是上線鎖在人工審核。

1
依任務裝工具

簡報站：npm、wrangler；產 PPT／處理資料：python-pptx；提交與開 PR：gh

2
改碼

裝好再改 presentations 或業務程式，自己先檢查過

3
開 PR

推 branch，用 gh 開 Pull Request，把 diff 攤給人看

4
人工合併／上線

merge 與 deploy 還是人確認，不讓 Agent 直接上線

人負責最後一哩：Agent 可以選工具、寫設定、開 PR，合併和部署仍由人把關。

10 / 帶走三句

當顧問就好，別當採購委員會

它很會講理由，但三個 Agent 常給三種理由。課堂上或多問一句：「你為什麼選它？哪些候選被刷掉？」

01
顧問，不是採購會

聽它的理由，自己做決定。重要安裝前，先看限制條件。

02
上下文就是最大的 prompt

語言、框架、現有服務，都會強烈影響它覺得「合理」的答案。

03
被點名還不夠

決戰點在文件、定價、免費方案限制，以及你是不是把功能綁太滿。
