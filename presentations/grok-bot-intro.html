02 / 它是什麼

具名 AI 隊友，加上一台常駐雲端電腦

SpaceXAI 與 Cursor 生態中的 AI 隊友產品：像傳訊息給同事一樣把任務交出去。

01
有名字、有職責

可建立一個或多個 Bot；同一 Bot 可在桌面與手機接續，不必重講一遍。

02
常駐雲端電腦

瀏覽器、檔案系統、終端機都在上面。你闔上筆電，工作仍可繼續。

03
做到結束

登入日常 App 與網站，跨工具收尾；需要你拍板時，它才回來找你。

官方說法：Bots 可以登入你日常使用的 App 與網站，把事情做到結束，而不是只給一段草稿。
Grok Bot · AI-PPT2 / 10

03 / 為什麼感覺不同

不只有對話框，而是能把路走完

01
有電腦，不只有對話框

可接 connectors／MCP；沒有乾淨 API 的網站，也能用電腦操作完成。

02
起手是一句話

建立 Bot、描述工作、按需要授權；不是先畫流程圖才開工。

03
多個 Bot 能協調

可平行做事、互傳訊息、進群組聊天，減少你當「人工路由器」。

04
會從示範學會流程

帶它走一遍，可存成 skill／routine，之後再跑或排程。

05
記憶會累積

具名 Bot 保有偏好與先前工作摘要；檔案與瀏覽器登入在帳號層級共享。

04 / 先把名字分清楚

Grok Bot ≠ Cloud Agents ≠ 聊天 Grok

名稱 比較像 工作主要發生在哪 你通常要驗收什麼
Grok Bot 常駐隊友／小團隊 雲端電腦、App、網站、跨工具流程 已落地的成果；必要時請你核准
Cursor Cloud Agents 專案內工程代理 程式庫（repo）、分支、測試、PR 可審查的程式變更與證據
Grok 對話產品 問答與創作 對話介面 想法、文字、即時回答
一句話：Grok Bot 擅長「跨工具把事情做完」；Cursor coding agent 擅長「在 repo 裡把程式改完」。兩者可以接力。

05 / 五類典型應用

結果要落在真實系統，不是沒人貼上的摘要

01
營運與行政收尾

整理發票、新進流程、通話逐字稿進 CRM 並起草後續。

02
銷售與外聯準備

從 CRM 拉複盤名單、補情報、起草符合你語氣的外聯草稿。

03
內容與研究

蒐集素材、產出可分享的 Google 文件／簡報骨架、對齊來源。

04
工程協調（不是取代 IDE）

Bot 當調度者：重現問題、開票、追蹤雲端代理、檢查截圖／PR。改碼交給 Cloud Agents。

05
小團隊分工

總管＋專責（收件匣、費用、招募、除錯、營運）；人只處理判斷與核准。

08 / 使用注意與最小起步

先做一件可檢查的真實任務

使用注意
  • 功能與方案可能調整，請以官方為準
  • 可搭配付費 Cursor 個人／Teams，或 SuperGrok／Plus／Heavy
  • 用量通常以週重置
  • 同一帳號下各 Bot 共享一台雲端電腦
  • 網站阻擋或需真人步驟時，交回給你；不要繞過安全關卡
最小起步
  • 安裝 App、建立具名 Bot
  • 交辦一件跨兩三種工具、結果可檢查的真實任務
  • 修正語氣與邊界後，再決定是否變成 routine
  • 涉及改程式時，明確要求開 Cloud Agent／PR
原則：你負責定義完成與風險；它負責在真實工具裡把路走完，並在該停的地方停下來問你。

09 / 結語

價值不在又多一個聊天視窗

Grok Bot 扛的是「做到快完成」與「真的完成」之間的那一截。

你
定義完成與風險

交付物、禁區、核准點。該停的地方，必須停下來問你。

Bot
在真實工具裡走完

信箱、日曆、文件、瀏覽器、專案下一站——結果落地，不是停在回覆。

Agent
在 repo 裡改完

Bot 收集需求與證據；寫碼交給 Cloud Agent；人核准後合併。
