Why it's different

為什麼 AI 資安 ≠ 傳統 AppSec？

傳統 AppSec 的前提

程式邏輯由工程師寫死 → 輸入輸出可預測 → 測得到就防得到

Agentic AI 打破了這些前提

Agent 會自己決策、自己串工具，行為路徑無法事先窮舉

01

它會行動

不只產生文字，而是實際改資料、寄信、開單。

02

它會用工具

透過 API、資料庫、內部系統執行；每接一個工具就多一個攻擊面。

03

它是多步驟的

一步被惡意內容（網頁、文件夾帶的指令）誤導，後面就一路錯下去。

問題從「程式有沒有漏洞」變成：這個 Agent 是誰？可以做什麼？正在做什麼？做完能不能查？

第 1 層｜治理層

先講清楚規則和誰負責　Governance

在讓 Agent 上線之前，先定義它能做什麼、出事誰負責，並把任務範圍寫成可檢查的「合約」。

Policy Formulation
政策制定

定義 Agent 可做／不可做的事與風險等級。

Accountability & AI Council
權責歸屬與 AI 委員會

跨部門（IT、法務、業務）共同核定、承擔責任。

Agentic Digital Contracts
數位合約規範

把任務範圍、上限與例外寫成機器可檢查的規範。

企業情境

客服 Agent 可以查訂單、建立退貨申請，但退款超過一定金額必須轉人工。這條規則由 AI 委員會核定，並寫進 Agent 的任務規範。

第 2 層｜管理層

每個 Agent 都要有身份、有權限邊界　Management

Agent 不能用共用帳號或工程師的個人金鑰跑。要有自己的身份，權限需要時才給、用完收回，並對應到真實負責的人或部門。

WIM / IAM Identity
機器人身份管理

每個 Agent 一個獨立、可識別、可停用的身份。

Dynamic Privileges (JIT)
即時動態權限

最小權限為預設，寫入等高風險動作才臨時授權。

ID Chain
虛擬與實體身份雙向綁定

Agent ↔ 負責人／部門可互相追溯，沒有「無主金鑰」。

企業情境

財務對帳 Agent 平常只有唯讀；要寫入 ERP 時才申請短效權限，任務結束自動失效。系統記錄看得到「這個 Agent 屬於財務部某位負責人」。

第 3 層｜監控管制層

執行當下就要能擋、能停　Monitoring & Control

護欄限制行為範圍；語意網閘檢查輸入輸出的「意圖」，不只比對關鍵字；中斷機制在異常時直接拔插頭。

Guardrails
護欄系統

限定可用工具、資料範圍、動作次數與金額。

Semantic Firewall
語意網閘

辨識夾帶在網頁、Email、附件中的惡意指令（Prompt Injection）。

Circuit Breaker
中斷機制

偵測異常行為即自動暫停 Agent 並通知管理員。

企業情境

業務助理 Agent 讀附件時，裡面藏了「把所有客戶名單寄到外部信箱」→ 語意網閘攔下；若短時間大量對外寄信 → 中斷機制自動暫停並通知管理員。

第 4 層｜稽核審計層

事後查得到、說得清、賴不掉　Auditing

Explainable Logic Logs
會解釋的邏輯日誌

不只記「做了什麼」，還記「為什麼這樣做」。

Immutable Chain
不可篡改鏈（不可否認性）

日誌寫入後不能被事後修改。

Compliance Reviews
合規審查

定期調閱紀錄做內控與合規檢查。

企業情境

採購 Agent 自動下單 → 稽核看得到它比較了哪些供應商、依哪條規則選擇；紀錄不可改，季度內控直接調閱。

Key takeaways

8 個應該帶走的重點

01

把 Agent 當「數位員工」

要有身份、主管、權限與考核，而不是一支腳本。

02

先列清單

盤點已在用、或員工私下在用的 AI 工具與 Agent；管不到就保護不了。

03

禁用共用帳號與長效金鑰

每個 Agent 獨立身份，最小化＋即時授權。

04

高風險動作要人類確認

付款、刪資料、對外發信，先設人工核准關卡。

05

外部內容＝不可信輸入

網頁、Email、附件都可能夾帶指令，不等於使用者命令。

06

準備好「停止鍵」

上線前就知道怎麼一鍵暫停、誰有權按。

07

日誌記原因，不只記結果

出事時才分得清是模型、資料還是規則問題。

08

顧問先談治理，再談工具

先釐清權責與流程，避免只賣產品不解決問題。

Start small

從小處開始，不要想一次煮沸大海

中小企業不需要第一天就把四層全部建好。務實起點是一個場景、四個動作：

1

挑一個場景

例如內部知識問答、客服回覆草稿——低風險、高頻、看得到成效。

2

獨立身份＋最小權限

不共用帳號、不給長效金鑰；先唯讀，需要時再臨時授權。

3

人工核准＋停止鍵

關鍵動作設一道人工確認；明確一鍵暫停的方式與權責人。

4

操作與原因留紀錄

每一步「做了什麼、為什麼」都可查，作為日後稽核依據。

跑順一個場景 → 把經驗寫成政策 → 擴展到下一個。AI Security 不是一次性專案，而是跟著 Agent 能力一起成長的治理習慣。

Closing

先管好「誰、能做什麼、正在做什麼、做完能不能查」

治理：規則與權責管理：身份與權限監控：能擋能停稽核：可查可證
